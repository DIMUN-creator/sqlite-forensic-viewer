# SQLite Forensic Viewer

암호화되지 않은 SQLite/DB 파일을 **원본을 훼손하지 않고** 분석하는 데스크톱 포렌식 도구입니다.
삭제된 레코드를 구조까지 복원하고, 대화를 재구성하며, 검증 가능한 리포트를 생성합니다.

표준 라이브러리(파이썬)만으로 동작하며, **모든 분석은 로컬에서만** 이뤄집니다.
어떤 데이터도 외부로 전송하지 않습니다.

---

## 주요 기능

- **파일 찾기** — PC의 주요 위치에서 SQLite 파일을 자동 탐색. 확장자가 아니라 파일 내용(매직 넘버)으로 판별하므로, 확장자가 없는 크롬 `History`나 위장된 파일도 잡아냅니다.
- **원본 보호 · 무결성 검증** — 파일을 열면 즉시 읽기 전용 사본을 만들고, 원본과 사본의 SHA-256 해시를 비교해 훼손이 없음을 증명합니다.
- **데이터 탐색** — 테이블·스키마·데이터를 페이지 단위로 조회.
- **타임스탬프 변환** — Unix(초/밀리/마이크로), Windows FILETIME, WebKit/Chrome, Apple Cocoa, SQLite Julian day를 모두 해석.
- **삭제 레코드 복원** — SQLite 레코드 포맷을 직접 파싱해 지워진 행의 컬럼값(보낸이·시간·내용)을 되살립니다. 스키마 자료형으로 검증해 오탐을 제거합니다.
- **대화 재구성** — 메시지 테이블 또는 카카오톡 내보내기(.txt)를 대화 형태로 표시하고, 복원된 삭제 메시지를 원래 시간 위치에 `[삭제됨]`으로 끼워 넣습니다.
- **통계** — 보낸이별 메시지 수, 시간대별 분포, 삭제가 많은 보낸이 등.
- **HTML/텍스트 리포트** — 무결성·통계·삭제 복원·대화를 담은 자체 완결 문서 생성.

## 설치 및 실행

파이썬 3.8 이상만 있으면 됩니다. **별도 의존성이 없습니다** (표준 라이브러리만 사용).

```bash
python viewer.py
```

- Windows 공식 파이썬에는 tkinter가 기본 포함되어 바로 실행됩니다.
- Linux는 `sudo apt install python3-tk` 가 필요할 수 있습니다.

---

## 사용법

1. `python viewer.py` 실행
2. **파일 찾기** 탭에서 SQLite 파일을 찾거나, **증거 파일 열기**로 직접 선택
3. **증거** 탭에서 무결성 해시 확인
4. **탐색** 탭에서 데이터 조회 (시간 컬럼 더블클릭 → 자동 변환)
5. **대화보기** 탭에서 메시지 테이블을 대화로 표시 (삭제 복원 포함)
6. **통계** 탭에서 분석
7. **리포트** 탭에서 HTML 문서 저장

`samples/` 폴더의 `sample_evidence.sqlite`로 모든 기능을 바로 연습할 수 있습니다.

## 작동 원리

포렌식 3대 원칙을 코드로 구현합니다.

1. **원본 불변성** — 원본을 열지 않고 읽기 전용 사본으로만 작업
2. **무결성 검증** — 원본/사본 해시 비교로 훼손 없음을 증명
3. **재현 가능성** — 모든 분석은 결정적이며 리포트로 기록

### 삭제 복원의 원리

SQLite는 행을 `DELETE`해도 바이트를 즉시 지우지 않습니다. 삭제된 데이터는
페이지 안의 미사용 공간(freeblock, unallocated)에 남거나, 페이지가 통째로
비워지면 프리리스트(freelist)로 이동합니다. 이 도구는 그 영역들을 훑어
SQLite 레코드 포맷(varint 헤더 + serial type + 값)을 직접 파싱하고,
테이블 스키마의 자료형과 일치하는 것만 채택해 오탐을 걸러냅니다.

## 복원 정확도 (검증 결과)

`validate.py`는 정답을 아는 상태에서 여러 조건의 복원 성능을 자동 측정합니다.
아래는 2000행 데이터 기준 측정값입니다.

| 시나리오 | 복원율 | 정밀도 |
|---|---|---|
| 대량 삭제 (절반) | **90.5%** | 92.5% |
| 기본 삭제 (VACUUM 안 함) | 76.2% | 80.7% |
| 소량 삭제 | 6.0% | 9.7% |
| VACUUM 실행 후 | 0% | — |
| secure_delete 켜짐 | 0% | — |
| auto_vacuum 켜짐 | 2.0% | 44.4% |

- **복원율(Recall)** = 지운 것 중 되살린 비율
- **정밀도(Precision)** = 복원한 것 중 진짜 비율

**해석**: 여러 행을 한꺼번에 지운 경우(실무에서 가장 흔한 상황) 90% 이상 복원됩니다.
소량 삭제는 SQLite의 페이지 조각모음이 흔적을 덮어써 복원율이 낮습니다.
`VACUUM`·`secure_delete`는 데이터를 물리적으로 제거하므로 복원이 불가능하며,
이는 모든 포렌식 도구의 공통 한계입니다.

직접 검증하려면:

```bash
python validate.py   # 결과 표 출력 + validation_report.csv 저장
```

## 한계

- **암호화된 DB는 다루지 않습니다.** 카카오톡·시그널 등 암호화 저장소는 대상이 아닙니다. 카카오톡 대화는 앱의 정식 내보내기(.txt) 파싱만 지원합니다.
- `VACUUM` 또는 `secure_delete`가 적용된 경우 삭제 복원이 불가능합니다.
- 삭제 복원은 best-effort이며, 정밀도 100%를 보장하지 않습니다 (검증 표 참고).

## 법적 고지 및 윤리

이 도구는 **본인 소유 데이터, 또는 정당한 권한·동의가 있는 데이터**의 분석만을
목적으로 합니다.

타인의 데이터를 동의나 법적 권한 없이 열람·수집·분석하는 것은 통신비밀보호법,
정보통신망법 등 위반이 될 수 있으며, 그로 인한 책임은 전적으로 사용자에게 있습니다.
이 도구는 암호화를 우회하거나 접근 권한을 획득하는 기능을 제공하지 않으며,
이미 접근 권한이 있는 평문 데이터의 분석만 수행합니다.

교육·연구·본인 데이터 관리·정당한 포렌식 조사 목적으로만 사용하십시오.

## 파일 구성

| 파일 | 역할 |
|------|------|
| `viewer.py` | GUI (tkinter). 실행 진입점. |
| `engine.py` | 분석 코어 (GUI 비의존). 모든 포렌식 로직. |
| `finder.py` | SQLite 파일 탐색기 (단독 실행 가능). |
| `validate.py` | 복원 정확도 자동 검증 하니스. |
| `test_engine.py` | 엔진 기능 테스트. |
| `samples/` | 연습용 샘플 데이터. |

엔진과 GUI가 분리되어 있어 로직을 단독으로 테스트·재사용할 수 있습니다.
